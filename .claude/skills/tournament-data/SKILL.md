# 大会運営のデータベースに入れる・直す

運営画面はログインすると、データベース（Cloudflare D1。`tournament/worker/catalog.ts`）の大会を並べ、選ぶとそのまま端末に入ってエントリー受付に進む。
ふりがな辞書もログイン時に自動で端末に取り込む。**ファイルを置くのではなく、JSON で直接書く**。形は `GET /api/schema`（ログイン不要）と README の「大会運営のデータベース」。

## コマンド（リポジトリの直下から。Node 22 以上）

```bash
C="node --experimental-strip-types --no-warnings tournament/scripts/catalog.mts"
$C list                                        # 大会（日程だけ／運営できる／終了）と辞書の件数
$C show <id>                                   # 大会 1 件の JSON
$C season <大会日程.xlsx>                      # 年間日程を「日程だけ」で入れる（ドローの入った大会は触らない）
$C draw <ドロー.xlsx> [--id <id>] [--name 正式名] [--courts 16]   # ドローを入れて「運営できる」に（同じ日の日程に重なる）
$C put <大会.json> --id <id>                   # JSON をそのまま入れる（画像・PDF から起こしたドローなど）
$C dict <ふりがな.xlsx> [所属.xlsx] [--merge]  # 辞書（列: 氏名・ふりがな・所属・確認メモ／所属名・ふりがな）。既定は置き換え
$C status <id> <planned|ready|done>
$C remove <id>
$C results <id> <結果.json> [--source 手描きのドロー表]   # 試合結果を受け箱へ（運営中の端末が 20 秒ほどで取り込む）
$C results <id>                                # 受け箱の中身／ --clear で空にする
node tournament/scripts/data.mjs token         # 外の仕組み用の送信用の鍵（1 度だけ表示）
```

id は協会サイトの大会ページと同じ名前（`r8-kensen-singles` など。`src/features/catalog/fromExcel.ts` の SLUGS）。
Cloudflare の API トークン（Workers Scripts: Edit）は役員ログインと同じもの（`officer-login` スキル）。

## サイトにドローを載せたら、運営システムも運営できる状態まで進める（決まり）

協会サイトの大会（管理画面の「要項・申込用紙・ドロー・結果・当日の写真」）にドローを載せたとき、または載せるよう頼まれたときは、
頼まれなくても続けて次の 1〜5 まで一通り進める。サイトだけ更新して終わらない。

1. `list` でその大会の id を確かめる（サイトの slug と同じ。`r8-kaicho-autumn` など）。無ければ `season` の日程を確かめ、id を決める
2. ドローを起こす：Excel があれば `draw`。画像・PDF だけなら読み取って JSON を作り `put`（下の表）。
   - 氏名の姓と名の区切りは辞書（`GET /api/dict`）の表記に合わせる。辞書に似た人がいれば読み違いを疑う（例「枚山」→ 辞書の「杦山 克弥」）
   - リーグ戦は **1 リーグ＝1 種目**（`男子B級ダブルス Aリーグ`）で `isRoundRobin: true`、`drawSize` はチーム数、position は ①② の番号。
     専用コートは `leagueCourts`（例 `["2","3"]`）、開始時刻は `eventStartTime`。試合順は運営画面が 4 チーム ①-② ③-④ ①-③ ②-④ ②-③ ①-④、3 チーム ①-② ②-③ ①-③ で組む
   - 試合形式は roundGameRules（ruleText と games）に、コート割り・順位の決め方など JSON に入らない決まりは大会の note に書く
3. `show <id>` で種目・人数・ペアをドローと 1 組ずつ照らし合わせる
4. 辞書に無い選手のふりがなを `PUT /api/dict`（merge）で足す。自信のない読みは note に「読み不明（○○ の可能性）」と書く（画面で「要確認」に出る）
5. 利用者に伝える：入れた種目・人数、辞書に足した人と要確認の人、運営システムで表せずに残ったもの（下）、
   当日の担当が大会選択の「確認して運営をはじめる」で確かめて直せること

いまの運営システムで表せないもの（入れずに残し、利用者に伝える）：予選リーグの順位で組む **順位別トーナメント**（「B1位」「C2位」のような枠）。
リーグの結果が出るまで選手が決まらないため、大会データには入らない。

## 頼まれごとと、すること

| 頼まれごと | すること |
| --- | --- |
| ドローの Excel を渡されて「入れて」 | `draw`。出力の種目・人数を伝える。同じ日の日程が無いと新しい大会になるので、そのときは id を確かめる |
| ドローが画像・PDF しか無い（サイトに載っているものなど） | 画像を読み、枠番号（BYE の位置）・シード・試合時刻・試合形式を起こして tournament の JSON を作り `put`。BYE は書かず、枠番号 position で位置を表す。2回戦以降の時刻は roundMatchTimes（`R{回戦}-{何試合目}`）。入れたら `show` で人数・シードを画像と照らし合わせる |
| 「今週の大会を運営できるようにして」 | `list` でその日の大会を見て、ドローを入れる。運営画面の「大会選択」に「運営できる」で出ることを伝える |
| ふりがなの直し・追加 | `dict … --merge`、または `PUT /api/dict`（merge）で必要な人だけ。自信のない読みは note（確認メモ）に理由を書く（画面で「要確認」に出る） |
| 年度の大会日程が来た | `season` |
| 何が入っているか | `list` |
| 手描きのドロー表（赤ペンで勝ち上がり・スコアを書いたもの）の写真を渡されて「反映して」 | 下の「手描きの結果を反映する」 |

## 手描きの結果を反映する

途中経過（その時点までに終わった試合だけ）でよい。運営中の端末は受け箱を 20 秒おきに見て、まだ入っていない結果だけを入れ、勝った人を次の回戦へ上げる。

1. `list` で大会を決め、`show <id>` で種目名（`draw.events[].eventName`）と枠ごとの選手名を出す。**種目名・選手名はこの表記に合わせる**（写真の見出し「男子シングルス A 級」が「一般男子シングルス」なら後者）
2. 写真を読む。赤い線が上に伸びている側が勝ち。線の横・交点の数字がその試合のスコア（勝った側の数字が大きい）。読み方の決まり：
   - `8-3`・`8 3` のように書かれた 2 つの数字 → 勝った人から見て `8-3`。タイブレークは `8-7(5)`
   - `RET`（途中棄権）→ そこまでのスコアに note `RET`（例 score `6-1`, note `RET`）
   - `W.O`・`off`・名前に横線（欠場）→ 相手の不戦勝。score `""`, note `W.O`
   - 1 回戦が無い枠（BYE）は書かない。線が途中で止まっている試合（まだ終わっていない）も書かない
   - 読めない・自信のない数字は推測で入れず、利用者に確かめる
3. 結果の JSON を scratchpad に作る（個人名が入るのでリポジトリに置かない）：
   ```json
   { "events": [{ "event": "一般男子シングルス", "matches": [
     { "winner": "北畠 史基", "loser": "渕上 雅博", "score": "8-3" },
     { "winner": "森田 進", "loser": "岡田 裕介", "score": "", "note": "W.O" }
   ] }] }
   ```
4. `results <id> <結果.json> --source 手描きのドロー表` で入れ、`results <id>` で中身を写真と照らし合わせる。同じ 2 人の結果は上書きになるので、直すときも同じコマンドでよい
5. 運営画面に「手描きのドロー表から N 試合を反映しました」と出ること、端末ですでに別の結果が入っていた試合は上書きされず「食い違い」として出ることを伝える

## 守ること

- 全角の英数字はデータベースが自動で半角にそろえる。所属の表記ゆれ（Love ALL／LoveALL など、全角・半角以外の違い）は自動では寄せないので、頼まれたら `PUT /api/dict` で直す
- 入れたドローは、運営画面の「ドロー確認」（大会選択の「確認して運営をはじめる」）で当日の担当が確かめて直せる。入れたあとはそこを見るよう伝える

- 名簿など個人情報を含むファイルはリポジトリに入れない（scratchpad などに置いて送る）
- 結果はスクリプトの出力どおりに伝える。`list`・`show` で確かめていないことを「入った」と言わない
- ドローの入った大会を `season` で上書きしない（スクリプトは自動で飛ばす）。入れ直すときは `draw` か `put`
