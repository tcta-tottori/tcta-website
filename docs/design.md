# Visual Design System — 鳥取市テニス協会 公式サイト

本ファイルは、AIエージェント（Claude Code 等）が本サイトのUIコード（Astro / HTML / CSS / React）を生成する際に参照するデザイン仕様書です。**UIを構築する際は、必ずこのルールに従ってください。**

- 対象サイト: 鳥取市テニス協会 公式ホームページ（リニューアル）
- 想定構成: Astro + microCMS + Cloudflare Pages
- **Version 3.0 / 2026-08-13** — LP変更にともなう全面改訂（v1.0ブルー案・v2.0サンド案は破棄）

## 1. トーン＆マナー

### 1.1 ブランドイメージ

| 軸 | 方向性 |
| --- | --- |
| 第一印象 | **清潔・端正・信頼できる**（白地に赤、余計な色を置かない） |
| 素材感 | 白い余白、直角、細い罫線。曲線と影は最小限 |
| 人物像 | 地域に根ざした公的団体としての誠実さ |
| 情報の姿勢 | 正確・整然・迷わせない |
| 温度感 | きびきびとして前向き。ただし騒がしくない |

### 1.2 コンセプト

> **つなぐ、広がる、テニスの輪。**

白を基調とし、**赤は「入口」にだけ置きます**。見出しラベル、ボタン、バッジ、アイコンの一部、そして装飾のスクエア。それ以外はすべて白・黒・グレーで組みます。この配分を守ることが、このデザインの品位そのものです。

### 1.3 デザイン原則（迷ったときの判断基準）

1. **赤は面積で使わない。** 赤い面は画面の5%以下に収める。広い赤面を作りたくなったら、写真か白に置き換える。
2. **色を増やさない。** 赤1色＋無彩色のみ。分類・強調・状態、すべてこの範囲で表現する。
3. **角を丸めない。** カード・ボタン・バッジはすべて直角または最大4px。丸みは親しみやすさを出すが、端正さを失う。
4. **罫線は細く、影は薄く。** `1px` の罫線で区切り、影は「浮いている」と分かる最小限に。
5. **50代以上の会員も主要ユーザー。** 本文14px以下を使わない。タップ領域は44px以上。
6. **写真は明るく、空を入れる。** 屋外・順光・青空。暗い室内写真は使わない。

### 1.4 シグネチャー要素（このサイトを記憶させる1点）

**レッドスクエア（Red Square）** — TCTAロゴの赤いドットを拡大した、正方形の赤いブロック。

- サイズ: `24px` / `40px` / `64px` の3種のみ。中間サイズを作らない。
- 配置: セクションの端で**画面外へ半分はみ出させる**（左右いずれかの端に接地）。中央に置かない。
- 色: `--red` 単色。グラデーション・透明度・角丸をかけない。
- **1画面（スクロール1回分）につき最大1つ。** 4つ以上並べると装飾に見えます。
- `aria-hidden="true"` を付与し、装飾として扱うこと。

補助のシグネチャー:

| 要素 | 仕様 |
| --- | --- |
| **ハーフトーンドット** | `--gray-300` の円（直径2px・間隔12px）のグリッド。大会情報セクションの右端に配置。`opacity: .6` |
| **ウェーブライン** | ごく淡い曲線（`--gray-200` / `1px`）。「大会カレンダー」セクション背景にのみ使用 |

### 2.2 無彩色

| `--gray-800` | `#3D3D3D` | 本文テキスト | 11.0:1 |
| `--gray-600` | `#5A5A5A` | **状態バッジ（非進行）の塗り**、サブテキスト | 6.90:1 |
| `--gray-500` | `#6E6E6E` | 日付、補足テキスト | 5.10:1 |

> 📌 **背景は白（`#FFFFFF`）が基本です。** セクションを塗り分けたいときだけ `--gray-050` を使い、それ以外の背景色は作らないでください。

### 2.3 🔴 バッジカラー統一ルール（最重要）

**バッジの色相は赤1系統に統一します。** 分類ごとに色を変えることはしません。

#### 設計の考え方

バッジには「**いま何ができるか（状態）**」と「**これは何の情報か（分類）**」の2種類があります。重要度が違うので、**色相ではなく塗りの強さで階層化**します。

```
強  ■ Solid Red      いま行動できる      → 受付中
中  ▢ Outline Red    分類ラベル          → 大会 / 結果 / お知らせ / ジュニア
弱  ■ Solid Gray     いま行動できない    → まもなく受付 / 受付終了 / 終了
例外 ■ Solid Ink + ⚠  中止・延期のみ
```

#### バッジ定義

| 階層 | スタイル | 背景 | 文字色 | 枠線 | 使用ラベル | コントラスト |
| --- | --- | --- | --- | --- | --- | --- |
| **L1 状態（進行中）** | Solid Red | `--red` `#D8232A` | `#FFFFFF` | なし | 受付中 | 5.01:1 ✓ |
| **L2 分類** | Outline Red | `transparent` | `--red` `#D8232A` | `1px solid --red` | 大会／結果／お知らせ／ジュニア | 5.01:1 ✓ |
| **L3 状態（非進行）** | Solid Gray | `--gray-600` `#5A5A5A` | `#FFFFFF` | なし | まもなく受付／受付終了／終了 | 6.90:1 ✓ |
| **例外 中止・延期** | Solid Ink + アイコン | `--ink` `#1A1A1A` | `#FFFFFF` | なし | ⚠ 中止／⚠ 延期／⚠ 会場変更 | 17.4:1 ✓ |

#### ⚠️ 中止告知についての重要な注意

**このデザインでは赤がブランドカラーなので、赤に「警告」の意味を持たせられません。** 前バージョンまでは赤＝中止でしたが、いまや赤は「受付中」です。取り違えると事故になります。

そのため中止・延期は、以下の3点を**必ずセット**で実装してください。バッジの濃さの違いだけで「受付終了」と区別させないこと。

1. **バッジに ⚠ アイコンを必ず付ける**（テキストラベルとアイコンの併用）
2. **ページ最上部に通知バーを表示する**（背景 `--ink` / 文字 `#FFFFFF` / 全幅）
3. **該当カードの画像に斜線ハッチを重ねる**（`--ink` を `opacity: .55`）

#### バッジ共通仕様

```css
.badge {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  min-width: 64px;              /* 幅は固定せず最小幅で揃える */
  height: 26px;
  padding: 0 10px;
  border-radius: 2px;           /* ほぼ直角。ピル型にしない */
  font-family: var(--font-body);
  font-size: 12px;
  font-weight: 700;
  letter-spacing: .06em;
  line-height: 1;
  white-space: nowrap;
}
```

- **1つの要素に2つのバッジを並べない。** 状態を優先し、分類は別の位置にテキストで置きます。
- **色だけで区別しない。** ラベルテキストを必ず併記します。
- **CMSに「バッジの色を選ぶ」項目を作らない。** 状態フィールドから自動で決まる設計にしてください。運用者が色を選べると統一が崩れます。

## 3. タイポグラフィ (Typography)

### 3.1 フォントファミリー

| 役割 | フォント | 用途 |
| --- | --- | --- |
| **和文（全般）** | `"Noto Sans JP"` | 見出し・本文・バッジ・フォーム。**1書体で通します** |
| **欧文・数字** | `"Barlow"` | Eyebrow（TOURNAMENT / NEWS）、日付、SCROLL、VIEW ALL、ロゴ英字 |

```css
--font-jp:    "Noto Sans JP", "Hiragino Sans", "Yu Gothic", sans-serif;
--font-latin: "Barlow", system-ui, -apple-system, sans-serif;
```

読み込みウェイトは **400 / 500 / 700 のみ**（`display=swap`）。

> 💡 **和文を1書体に絞る理由。** このデザインは白と赤の対比が主役なので、書体で表情を足す必要がありません。Noto Sans JP はウェイト差が明快で、700 の見出しと 400 の本文だけで十分な階層が作れます。
>
> **Barlow を選んだ理由。** Eyebrow の「TOURNAMENT」や日付の「2026.10.18」は、やや縦長で機械的な字面が合います。Barlow はわずかにコンデンスされたグロテスクで、字間を開けた大文字組みにしたときに端正に収まります。Montserrat は字面が丸く広いため、この直角基調のレイアウトでは緩んで見えます。

### 3.2 タイプスケール

ベースフォントサイズ `16px` (1rem)。

| 要素 | Desktop | Mobile | ウェイト | line-height | letter-spacing |
| --- | --- | --- | --- | --- | --- |
| h1（ヒーロー） | `52px` | `30px` | 700 | 1.5 | `0.02em` |
| h2（セクション） | `34px` | `25px` | 700 | 1.4 | `0.04em` |
| h3（カードタイトル） | `18px` | `17px` | 700 | 1.6 | `0.02em` |
| h4 | `16px` | `16px` | 700 | 1.6 | `0.02em` |
| Lead（リード文） | `15px` | `15px` | 400 | 2.0 | `0.03em` |
| p（本文） | `16px` | `16px` | 400 | 1.9 | `0.03em` |
| small（補足） | `14px` | `14px` | 400 | 1.8 | `0.03em` |
| Eyebrow（英字） | `13px` | `12px` | 700 | 1.4 | `0.12em` |
| 日付（Latin） | `14px` | `13px` | 500 | 1.4 | `0.04em` |
| Badge | `12px` | `12px` | 700 | 1 | `0.06em` |

```css
h1 { font-size: clamp(1.875rem, 4.2vw, 3.25rem); }
h2 { font-size: clamp(1.5rem, 2.8vw, 2.125rem); }
```

### 3.3 見出しの構造ルール

各セクションの見出しは、**Eyebrow（赤・英字） → h2（黒・和文）** の2段構成に統一します。

```
TOURNAMENT             ← --font-latin / 13px / 700 / letter-spacing .12em / --red / uppercase
大会情報                ← --font-jp / h2 / 700 / letter-spacing .04em / --ink
```

- Eyebrow と h2 の間隔は `--space-1`（8px）。
- **Eyebrow は必ず赤。** これがこのサイトで最も繰り返される赤の用法です。
- 中央揃えの見出しを使う場合は、h2 の下 `--space-3` にレッドスクエア（`24px`）を中央配置します。

### 3.4 和文組版の注意

- **禁則処理:** `word-break: normal;` `overflow-wrap: anywhere;` `line-break: strict;`
- **改行位置:** キャッチコピーは意味の単位で改行します（「つなぐ、広がる、／テニスの輪。」）。`<br>` ではなく `<span class="nowrap">` で制御。
- **句読点:** 見出し末尾の「。」は残します（LP準拠）。省略しないこと。
- **見出しの字間は詰めない。** 和文見出しは `0.02〜0.04em`。太いゴシックは字間を開けないと詰まって見えます。
- **行長:** 本文の1行は全角36文字程度（`max-width: 40em`）を上限とする。

## 4. スペースとレイアウト (Spacing & Layout)

### 4.1 スペーシングトークン

8pxグリッド（ベース4px）を基準とします。

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--space-px` | `4px` | アイコンと文字の間 |
| `--space-1` | `8px` | Eyebrowと見出しの間 |
| `--space-2` | `16px` | 標準的な余白、カード内の行間 |
| `--space-3` | `24px` | カード内padding、要素グループ間 |
| `--space-4` | `32px` | 小見出しと本文ブロックの間 |
| `--space-5` | `48px` | 見出しブロックとコンテンツの間 |
| `--space-6` | `64px` | セクション内の大きな区切り |
| `--space-7` | `88px` | セクション間（タブレット） |
| `--space-8` | `112px` | セクション間（デスクトップ） |

### 4.2 セクション余白の法則

| 画面幅 | セクション上下padding |
| --- | --- |
| Mobile (~639px) | `64px` |
| Tablet (640〜1023px) | `88px` |
| Desktop (1024px~) | `112px` |

```css
.section { padding-block: 64px; }
@media (min-width: 640px)  { .section { padding-block: 88px; } }
@media (min-width: 1024px) { .section { padding-block: 112px; } }
```

### 4.3 コンテナと左右余白

| トークン | 値 |
| --- | --- |
| `--container-max` | `1200px` |
| `--container-narrow` | `760px`（記事本文、フォーム） |
| 左右gutter（Mobile） | `20px` |
| 左右gutter（Tablet以上） | `40px` |

ヒーロー、CTAバンド、フッター下帯、レッドスクエア、ドットパターンは**フルブリード**、中身のみコンテナ幅に収めます。

### 4.4 レイアウト方式

**CSS Grid / Flexbox を優先的に使用すること。** `float` や絶対配置でのレイアウト組みは禁止。

| ブロック | Mobile | Tablet | Desktop |
| --- | --- | --- | --- |
| 大会情報カード | 1.2列（横スワイプ） | 2列 | 4列 |
| お知らせリスト | 1列（日付・バッジを上段に折返し） | 1列 | 1列（横並び） |
| 大会カレンダー | 縦積み（リストのみ／埋め込み非表示） | 縦積み | 2カラム（リスト 5 : カレンダー 7） |
| リンク集 | 2列 | 3列 | 4列 |
| コート案内 | 縦積み（リスト→地図） | 縦積み | 2カラム（リスト 5 : 地図 7） |
| CTA | 縦積み（画像→文章） | 2カラム | 2カラム（画像 5 : 文章 7） |
| フッターリンク | 2列 | 2列 | 2列（ロゴ左・SNS右） |

グリッドの `gap` は Mobile `16px` / Desktop `24px`。

### 4.5 角丸（Radius）

```css
--radius-none: 0;     /* カード、画像、CTAブロック */
--radius-xs:   2px;   /* バッジ、ラベルチップ */
--radius-sm:   4px;   /* 入力欄、ボタン */
--radius-full: 9999px; /* 円形アローボタン、SNSアイコン */
```

> 📌 **カードとボタンは直角基調です。** `--radius-sm`（4px）を超える角丸を使わないでください。円形にしてよいのは、カルーセル矢印・SNSアイコン・トップへ戻るボタンだけです。

### 4.6 シャドウ（Shadow）

```css
--shadow-card:   0 1px 3px rgba(26, 26, 26, .06);
--shadow-hover:  0 6px 20px rgba(26, 26, 26, .10);
--shadow-header: 0 1px 0 rgba(26, 26, 26, .08);
```

影は「浮いていると分かる最小限」に留めます。カードは影より **`1px solid --gray-200` の罫線**を主とし、影は補助です。

## 5. コンポーネントスタイル (Components)

### 5.1 ヘッダー (Header)

- 高さ: Desktop `88px` / Mobile `64px`
- 背景: `--white`（ヒーローが白基調なので透過にしない）
- スクロール `100px` 以降: `--shadow-header` を付与。高さは変えない
- **右上端にレッドスクエア**（`40px`）を画面右端に接地させて配置
- **ロゴ:** 左端。上に和文「鳥取市テニス協会」（`--font-jp` / 12px / 500 / `--ink`）、下にTCTAマーク＋英字「TOTTORI-CITY TENNIS ASSOCIATION」（`--font-latin` / 8px / 500 / `letter-spacing: .1em` / `--gray-600`）
- **ナビ:** `--font-jp` / 15px / 500 / `--ink` / 項目間 `--space-5`

### 5.4 大会情報カード (Tournament Card)

## 7. モーション (Motion)

| 種類 | 仕様 |
| --- | --- |
| スクロール表示 | `opacity: 0 → 1` + `translateY(20px → 0)` / `duration: .7s` / `cubic-bezier(.22,1,.36,1)` |
| 連続要素のstagger | `100ms` ずつ遅延（カード、リンクカード、リスト行） |
| ホバー | `.3s ease`。移動は `3〜4px` |
| 画像ホバー | `scale(1.05)` / `.5s` |

| ページ遷移 | フェードのみ（`.3s`） |
| ヒーロー | h1 を行単位でフェードアップ（`140ms` stagger）→ タグライン → リード文 → ボタン |

```css
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```

## 9. アクセシビリティ (Accessibility)

**赤1色に多くの役割を負わせている配色なので、この章は装飾より優先します。**

- すべてのテキストは背景色とのコントラスト比 **4.5:1 以上**。大きな文字（24px以上 or 19px以上の太字）は 3:1 以上。アイコン・図形は 3:1 以上。
- 本仕様で検証済みの組み合わせ:

| 前景 | 背景 | 比 | 判定 |
| --- | --- | --- | --- |
| `--ink` `#1A1A1A` | `--white` | 17.4:1 | ✓ |
| `--gray-800` `#3D3D3D` | `--white` | 11.0:1 | ✓ |
| `--gray-500` `#6E6E6E` | `--white` | 5.10:1 | ✓ |
| `--white` | `--red` `#D8232A` | 5.01:1 | ✓ 文字可 |
| `--red` `#D8232A` | `--white` | 5.01:1 | ✓ 文字可 |
| `--red` `#D8232A` | `--gray-050` `#F8F8F8` | 4.68:1 | ✓ |
| `--white` | `--gray-600` `#5A5A5A` | 6.90:1 | ✓ |
| `--white` | `--ink` `#1A1A1A` | 17.4:1 | ✓ |

- 画像には必ず `alt` 属性。装飾（レッドスクエア、ドットパターン、ウェーブライン）は `alt=""` + `aria-hidden="true"`。
- 見出しレベル（h1〜h4）を飛ばさず階層順に。1ページにh1は1つ。
- キーボードフォーカス:
  ```css
  :focus-visible {
    outline: 3px solid var(--red);
    outline-offset: 2px;
    border-radius: 2px;
  }
  ```
- リンクテキストは「こちら」単体を避け、行き先が分かる文言に。
- **赤は「受付中」「分類」「必須」「フォーカス」「エラー」に同時に使われます。** 色だけで意味を判断させないよう、すべてテキストラベルかアイコンを併記してください。特に**中止告知は §2.3 の3点セット**（⚠アイコン・通知バー・ハッチ）を必ず実装します。
- 地図を埋め込む場合は `title` 属性を付与し、住所テキストを地図の外にも記載する（地図が読めない場合の代替）。
- フォームは `<label for>` で関連付け、エラーは `aria-describedby` / `aria-invalid` で通知。
- PDFリンクには形式とサイズを明記（例: 「開催要項（PDF / 1.2MB）」）。
- カルーセルは自動再生しない。前後ボタンにそれぞれ `aria-label="前の大会へ"` / `"次の大会へ"` を付与。

## 10. 写真・画像のトーン

| 項目 | 指針 |
| --- | --- |
| 明るさ | **明るく、順光。** 青空が入るカットを優先する |
| 彩度 | 自然なまま。赤が主役なので、写真側に強い赤を入れない |
| 被写体 | プレー中の動きのある瞬間。引きすぎず、人物が判別できる距離 |
| 背景 | 空・コートの緑／ブルー。雑然とした背景は避ける |
| 加工 | モノクロ・強いフィルタは不可。統一トーンのLUTを1つ決めて全写真に適用する |
| 形式 | WebP（フォールバックにJPEG）。`srcset` で 1x / 2x |
| アスペクト比 | 大会カード `16:10` / ヒーロー `3:4`（縦位置・右半分）/ CTA `4:3` |
| 肖像 | 会員・ジュニアの顔が写る写真は、掲載許諾の確認を前提とする |

> ⚠️ **写真に赤い服・赤いコートが写り込むと、ブランドレッドと競合します。** 大会情報カードのサムネイルは、選定時に赤みの強いカットを避けてください。

## 11. エージェントプロンプトガイド (Agent Prompt)

AIエージェントへの指示です。コードを生成する際は、以下のルールを遵守してください。

1. **カラーコードや数値をハードコードしないこと。** 必ず本ファイルで定義した **CSS変数**（`var(--red)` など）または Tailwind のトークンを用いてください。赤以外の色相を追加しないこと。
2. **バッジを実装するときは §2.3 を必ず読むこと。** 分類ごとに色相を変えないでください。塗り赤・線赤・塗りグレーの3段階と、例外の黒1つのみです。**中止告知は必ずアイコン・通知バー・ハッチの3点セットで実装します。**
3. **日本語が不自然にならないよう、`letter-spacing` と `line-height` を適切に調整してください。** 和文本文は `line-height: 1.9` / `letter-spacing: 0.03em`、和文見出しは `0.02〜0.04em`、英字Eyebrowは `0.12em` が基準です。
4. **角を丸めすぎないこと。** カード `0`、ボタン・入力欄 `4px`、バッジ `2px`。円形にしてよいのはカルーセル矢印・SNSアイコン・トップへ戻るボタンのみです。
5. **未知のデザイン要素を生成する場合は、事前にユーザーに質問するか、このデザインシステムに準拠した形で提案してください。** 勝手に新しいコンポーネントスタイルを発明しないこと。
6. **セクション間の余白は `.section` クラスに集約し、個別要素の `margin` で調整しないこと。** CSSセレクタの詳細度が衝突し、余白が打ち消し合う事故を防ぎます。
7. **コンテンツはCMS（microCMS）から取得する前提でコンポーネントを組むこと。** 大会名、日付、施設情報をコンポーネント内に直書きせず、`props` として外から渡します。**バッジの状態は締切日から計算し、CMSに手入力させないこと。**
8. **文言（コピー）はユーザー視点で書くこと。** ボタンは動作をそのまま書く（「送信」ではなく「エントリーを申し込む」）。同じ動作は最初から最後まで同じ言葉を使う。
9. **完成前のセルフチェック:**
   ① 赤い面が画面の5%を超えていないか
   ② バッジに赤・グレー・黒以外を使っていないか
   ③ 中止バッジに ⚠ アイコンが付いているか
   ④ カードの角が直角か（4px超になっていないか）
   ⑤ レッドスクエアが1画面に2つ以上出ていないか
   ⑥ モバイル375px幅で（カード列以外に）横スクロールが出ないか
   ⑦ キーボードのTabでフォーカスが見えるか
   ⑧ 本文が14px未満になっていないか

## 12. 禁止事項（やらないこと）

- **赤・無彩色以外の色相を追加する**（青いリンク、緑の成功表示、黄色の注意喚起など）
- 赤い面を広く敷く（画面の5%超）
- **中止・延期を赤で表現する**（赤は「受付中」の意味です）
- 中止と受付終了を、バッジの濃さの違いだけで区別する
- カードやボタンの角丸を4pxより大きくする
- レッドスクエアを1画面に2つ以上置く／中央に置く／グラデーションや角丸をかける
- ボタンを1画面に2つ以上並べる（Solid Red ＋ Outline の組み合わせを除く）
- モバイルでGoogleカレンダーの埋め込みを表示する
- 予定をカレンダー埋め込みだけで見せる（テキストのリストを必ず併置する）
- リンク集をロゴ画像だけで並べる（団体名のテキストを必ず添える）
- リンク集のロゴを `width: 100%` で引き伸ばす
- 本文フォントサイズを14px未満にする
- 見出しを画像で作る（テキストで組む）
- CMSに「バッジの色を選ぶ」項目を作る／状態を手入力させる
- カルーセルを自動再生する
- 大会カードのサムネイルに赤みの強い写真を使う
- スクロールジャック、自動再生の音声、パララックスの多用
- 「詳しくはこちら」だけのリンク文言
