# サイト構成方針 v1.0 — ブロック編集への移行設計

このドキュメントは、鳥取市テニス協会サイトを
**「凝ったアニメーションのデザイン」と「スマホからのブロック単位の簡単更新」を両立させる**
構成へ移行するための設計方針をまとめたものです。

- 対象: 現行の静的HTML（10ページ・ビルド工程なし・GitHub Pages 公開）
- 決定事項: **土台 = Astro** / **管理画面 = microCMS** / **作業場所 = リポジトリを clone したローカルフォルダ**

---

## 1. 全体像

```
       ┌──────────────┐   スマホ・PCのブラウザから
       │   microCMS   │   ブロックを追加/並べ替え/文字修正
       │  （管理画面） │
       └──────┬───────┘
              │ Webhook（repository_dispatch）
              ▼
       ┌──────────────┐
       │GitHub Actions│   Astro でビルド（microCMS APIから本文取得）
       └──────┬───────┘
              │ 静的HTMLを生成してデプロイ
              ▼
       ┌──────────────┐
       │ GitHub Pages │   ← 閲覧者はここを見る
       └──────────────┘

  デザイン・アニメーションの開発は
  ローカル clone → git push → 同じ Actions でデプロイ
```

**要点**: 閲覧者に届くのは最後まで**静的HTML**です。
アニメーションの自由度もページ表示速度も検索エンジン対策も、今と同じかそれ以上を保てます。

---

## 2. 設計の中心原則：「デザイン固定・中身可変」

Jimdo のようなツールは「どんなブロックでも自由に置ける」代わりに、
置き方次第でデザインが崩れます。このサイトではその逆を採ります。

> **協会サイトに必要なブロック型だけを事前に定義し、
> 各ブロック型は完成した装飾とアニメーションを内蔵する。
> 編集者が触れるのは、文字・画像・並び順・表示ON/OFF だけ。**

これにより:

- スマホから何をどう編集しても、**デザインは絶対に崩れません**
- 行リビール、clip-path マスク、スクロール連動フェードは
  ブロック側に組み込み済みなので、**編集者が意識する必要がありません**
- 「余白を調整する」「色を変える」といった操作は管理画面に存在しません
  （そこはデザイン側の責務として、リポジトリ内で管理します）

## 3. ブロック型カタログ（初期案）

現行ページで既に使われているコンポーネントから抽出しました。
すべて `assets/css/style.css` の既存クラスをそのまま使うため、見た目は現状を維持します。

| # | ブロック型 | 用途 | 編集者が入力する項目 |
|---|---|---|---|
| 1 | `見出し＋本文` | 一般的な説明文 | 見出し、本文（リッチテキスト） |
| 2 | `パネル` | 補足・注意書きの囲み | 見出し、本文、色（通常／グレー） |
| 3 | `定義リスト` | 開催概要（日時・会場・費用…） | 項目名と値の繰り返し |
| 4 | `ステップ` | 申込の流れ・手順 | 手順名、説明の繰り返し |
| 5 | `Q&A` | よくある質問 | 質問、回答の繰り返し |
| 6 | `資料ダウンロード` | 要項・申込書PDF | 種別、タイトル、説明、注記、ファイル |
| 7 | `画像＋テキスト` | 写真つきの紹介 | 画像、見出し、本文、画像の左右 |
| 8 | `カード一覧` | コート案内など | 画像、タイトル、説明、リンクの繰り返し |
| 9 | `表` | 大会一覧・料金表 | 見出し行、データ行 |
| 10 | `埋め込み` | Googleカレンダー／マップ | 埋め込みURL、モバイル表示ON/OFF |
| 11 | `ボタン` | 申込ページ等への誘導 | ラベル、リンク先、種類 |

> ヘッダー／モバイルナビ／CTA／フッターは**ブロックにしません**。
> 全ページ共通の構造物なので、Astro のコンポーネントとして一箇所で管理し、
> 文言だけを後述の `settings` から差し込みます。
> （現状は10ファイルに同じマークアップが重複しており、これが解消されます）

## 4. microCMS の API 設計

**制約**: 無料の Hobby プランは **API 5個まで**・コンテンツ1万件まで。
この5枠に収まるよう設計します（メンバー数の上限は契約時に要確認）。

| # | API | 形式 | 内容 |
|---|---|---|---|
| 1 | `pages` | リスト | 各ページ本体。`slug` ＋ `title` ＋ **`blocks`（繰り返しフィールド）** |
| 2 | `news` | リスト | お知らせ（日付・カテゴリ・本文・リンク） |
| 3 | `tournaments` | リスト | 大会情報（年度・大会名・日程・会場・状態・要項PDF） |
| 4 | `results` | リスト | 大会結果（年度・大会名・結果PDF／順位表） |
| 5 | `settings` | オブジェクト | 通知バー、連絡先、リンク集、フッター文言など全ページ共通 |

**ブロック編集の実現方法**: microCMS の
[カスタムフィールド＋繰り返しフィールド](https://blog.microcms.io/intro-custom-repeatfield/)
を使います。ブロック型ごとにカスタムフィールドを1つ定義し、
`pages.blocks` をその繰り返しフィールドにすることで、
**管理画面上で「ブロックを追加 → 型を選ぶ → 中身を書く → ドラッグで並べ替え」**
という Jimdo に近い操作になります。

大会情報と結果を独立APIにしているのは、
**年度ごとに大量に増える情報を、ページ本文とは別に一覧管理するため**です。
これらはブロックではなく、専用の一覧ブロックが自動で拾って表示します。

## 6. 公開フロー

1. microCMS で内容を編集し「公開」
2. Webhook が GitHub Actions の
   [`repository_dispatch`](https://help.microcms.io/ja/knowledge/webhook-github-actions-settings)
   を発火
3. Actions が microCMS から本文を取得して Astro でビルド
4. GitHub Pages へデプロイ

**APIキーの扱い**: microCMS のキーは GitHub Actions の Secrets に置き、
**ビルド時のサーバー内でのみ使用**します。生成後のHTMLにキーは含まれないため、
外部に漏れることはありません。

### 期待値の調整（重要）

- **反映は即時ではありません。** 公開ボタンからサイト反映まで、ビルド時間ぶん
  **おおむね1〜3分**かかります。Jimdo の「保存した瞬間に反映」とは異なります。
- **microCMS の画面プレビュー機能は、この構成では下書きの即時確認に一手間かかります。**
  下書きプレビューが必要になった段階で、別途プレビュー用の仕組みを検討します。

いずれも、スマホからブロックを編集して数分後に公開される、という運用で問題ない前提です。

## 7. 移行の進め方

各段階を独立させ、**いつでも止められる／前段階に戻れる**ようにします。

| 段階 | 内容 | 完了の判断基準 |
|---|---|---|
| **0. 準備** | リポジトリを clone したローカルで作業する体制に。不要な `tottoritennissite.zip` を削除 | ローカルで `git pull` → 編集 → `push` が回る |
| **1. Astro化** | **見た目とアニメーションを1pxも変えず**、現行HTMLをコンポーネントに分解するのみ | 移行前後のスクリーンショットが一致し、全アニメーションが同じ動きをする |
| **2. ブロック化** | ブロック型11種を実装。まずリポジトリ内のJSONを入力として描画確認 | 各ページがJSONから再現される |
| **3. CMS接続** | microCMS にAPIを作成し、内容を移行。Actions自動デプロイを接続 | **スマホから文字を直して、サイトに反映される** |
| **4. 仕上げ** | 実写真への差し替え、PDF・外部リンク、フォーム送信先、`要確認` 項目の確定 | README「公開前に差し替えが必要なもの」が解消される |

**段階1が最大の山場であり、最も慎重にやるべき箇所です。**
ここでデザインとアニメーションが劣化しないことを確認できれば、以降は安全に進められます。
そのため段階1では、内容の変更を一切行いません。

## 8. この構成で確保されること

- **アニメーションの自由度** — 静的HTML出力なので、スクロール連動・
  View Transitions・WebGL まで制約なく使えます。既存の `main.js` はそのまま持ち込めます。
- **スマホからのブロック編集** — microCMS の管理画面は日本語で、
  スマホのブラウザから操作できます。将来ご自身以外の協会の方が更新する際も、
  Git や HTML の知識は不要です。
- **デザインが壊れない** — 編集できるのは事前に定義したブロックの中身だけです。
- **ロックインの回避** — 本文は microCMS の API から一括エクスポートでき、
  ページ構造とデザインはすべて GitHub リポジトリ側にあります。
  CMS を乗り換えても、サイトを作り直す必要はありません。

## 9. 注意点・未確定事項

- microCMS Hobby プランの**メンバー数上限は契約時に要確認**です。
  協会内で複数人が更新する場合、有料プランが必要になる可能性があります。
- **お問い合わせフォームの送信**は静的サイトでは完結しません。
  外部フォームサービス等の接続が別途必要です（README にも記載済み）。
- API 5個の制限があるため、**新しい情報の種類を増やす際は
  `pages` のブロック型として実装できないかを先に検討**してください。
