# 鳥取市テニス協会 公式サイト

鳥取市テニス協会（TOTTORI-CITY TENNIS ASSOCIATION）の公式サイトです。
[Astro](https://astro.build/) で静的HTMLを生成し、GitHub Pages で公開しています。
出力は素の静的HTMLなので、アニメーションの自由度と表示速度は制約を受けません。

## 構成

```
.
├── src/
│   ├── pages/            各ページ。URLはファイル名そのまま（about.astro → /about.html）
│   │   ├── index.astro          トップ（ヒーロー／大会カルーセル／お知らせ／
│   │   │                         リンク集／コート案内）
│   │   ├── tournaments.astro    大会情報（月ごとのカレンダー・全19大会・状態フィルタ）
│   │   ├── results.astro        大会結果（年度タブ）
│   │   ├── club.astro           クラブ対抗戦
│   │   ├── lesson.astro         水曜テニス教室
│   │   ├── tennis-day.astro     テニス祭り（テニスの日）
│   │   ├── membership.astro     協会登録（入会案内）
│   │   ├── about.astro          協会について
│   │   ├── links.astro          リンク集
│   │   └── contact.astro        お問い合わせ（入力検証・送信完了画面）
│   ├── layouts/Base.astro       <head>・通知バー・ヘッダー・CTA・フッターの土台
│   ├── components/              共通パーツ（下記「共通パーツ」を参照）
│   ├── config/nav.js            ナビゲーション定義の唯一の正
│   ├── data/tournaments.js      トップの大会カルーセルの唯一の正（写真の差し込み口）
│   ├── data/news.js             トップのお知らせの唯一の正
│   ├── data/schedule.js         令和8年度 全19大会（カレンダーの元データ）
│   └── data/courts.js           コート案内の一覧と地図の唯一の正
├── public/               そのまま公開される静的ファイル
│   ├── assets/css/style.css     デザイントークン＋全コンポーネント（1ファイル）
│   ├── assets/js/main.js        リビール／ヘッダー／カルーセル／フィルタ／タブ／フォーム
│   ├── assets/img/              画像・ファビコン
│   │   └── tournaments/         大会写真の置き場（入稿分をここに追加）
│   └── .nojekyll                GitHub Pages で Jekyll 処理を無効化
├── docs/                 設計資料（構成方針・デザイン仕様・原稿仕様・検討ログ）
├── .github/workflows/deploy.yml  ビルドして GitHub Pages へ公開
└── dist/                 ビルド出力（Git管理外）
```

## 設計資料

実装の根拠は [`docs/`](./docs/) にまとめています。

- [`docs/architecture.md`](./docs/architecture.md) — サイト構成方針 v1.0（ブロック編集への移行設計・段階計画）
- [`docs/design.md`](./docs/design.md) — ビジュアルデザイン仕様書 v3.1（配色・タイポ・余白・コンポーネント）
- [`docs/content.md`](./docs/content.md) — 原稿仕様書 v2.0（各ページの実テキストと `要確認` 項目）
- [`docs/design-chat-log.md`](./docs/design-chat-log.md) — ファーストビュー3案から採用案決定までの検討ログ

## ローカルでの確認

```bash
npm install     # 初回のみ
npm run dev     # http://localhost:4321 を開く
```

保存すると自動で再読み込みされます。公開されるものと同じ出力を確認する場合は:

```bash
npm run build && npm run preview
```

## 公開（GitHub Pages）

`main` への push で [`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml) が動き、
ビルド結果が自動で公開されます。

> **初回のみ設定変更が必要です。**
> リポジトリの Settings → Pages で **Source: GitHub Actions** を選択してください。
> 以前の **Deploy from a branch** のままだと、ビルド前のソースが公開されて表示が崩れます。

独自ドメインを使う場合は `public/CNAME` を追加してください（`public/` の中身はそのまま公開されます）。
ページ内のリンクはすべて相対パスなので、プロジェクトページ（`/tcta-website/` 配下）でも
独自ドメイン（ルート直下）でも設定を変えずに動きます。

## 実装メモ

- **デザイン基準** — 配色・タイポグラフィ・余白・バッジの規則はデザイン仕様書 v3.1 に準拠。
  CSS変数は `public/assets/css/style.css` 冒頭の `:root` に集約しています。
- **レスポンシブ** — モバイルファースト。ブレークポイントは `〜639px` / `640〜1023px` / `1024px〜`。
  375px幅で横スクロールが出ないことを確認済みです
  （大会カルーセルの横スワイプと、大会一覧表の横スクロールは仕様どおりの例外）。
- **ヘッダー** — 全ページ共通で白背景。下端に薄い黒の1px境界線を引き、ヒーロー写真は
  透けさせません。**画面上部には残しません**（スクロールすると一緒に流れます）。
  セクションの見出しも同様に貼り付けません。
  画面右上の赤い「お問い合わせ」ブロックは画面右端に幅160pxで固定され、
  ナビはその手前で止まるよう `padding-right` を計算しています。
  1023px以下は全ページ共通のハンバーガーメニュー。
- **ヒーローの高さ** — `calc(100svh - var(--header-h) - 1px)` でちょうど1画面ぶん。
  ヘッダーが追従しないので、この高さで次のセクションが覗かなくなります。
- **ヒーローの見出し位置** — デスクトップは左の列の上寄せに「PLAY BEYOND.」〜ボタンまでをまとめ、
  右に写真を置きます。モバイルは写真の上に重ねます（同じ格子のマスに置いて切り替えています）。
- **CSS・JS のキャッシュ対策** — `Base.astro` が中身のハッシュを URL に付けます
  （`style.css?v=xxxxxxxx`）。ファイル名を変えずに更新しているため、これが無いと
  ブラウザが古い CSS を使い続け、新しい HTML と噛み合わずに表示が崩れます。
- **画面いっぱいの帯** — 大会カルーセルとリンク集のマーキーはコンテナの外に出し、
  画面の端から端まで使います。カルーセルは1枚目だけ本文と同じ位置から始まるよう
  内側に余白（`--carousel-pad`）を取っています。
- **ヒーローの導入** — 写真を払ったあと、右上に大きく `PLAY`、続けて左下に `BEYOND.` を
  1語1秒で出して消し、そこから「PLAY BEYOND.」のキャッチコピーが動き出します。
  キャッチコピーは文字を1枚だけ置き、背景のグラデーションを文字型に切り抜いて流すことで
  面の色だけを変えています（2枚重ねると字がずれて立体的に見えるため重ねません）。
  続けて英字が左から1文字ずつ現れ、最後に赤い面が本文の下を左から右へ駆け抜けます。
  面は文字より下（`z-index:-1`）に敷き、赤の上に来た文字だけを白にしています
  （文字は1枚のまま、面の色だけを切り替え）。
  時刻の基準は `.hero` の `--intro-end`（既定 2s）で、0s にすれば導入なしで全体が前へ詰まります。
- **アニメーション** — 見出しの行リビール、写真のマスク表示（clip-path）、
  スクロール連動フェード＋stagger、リンクバナーのマーキー。
  マーキーは2段組みで、上段（テニス協会・連盟のHP）は右から左、下段（施設・クラブ・
  協賛など）は左から右へ流れます。段の振り分けは `src/data/links.js` の `row` です。
  `prefers-reduced-motion` に対応しています。
- **共通パーツ** — ヘッダー／モバイルナビ／CTA／フッター／通知バーは
  `src/components/` の各コンポーネントに一本化されています。
  1箇所を直せば全ページに反映されます（移行前は10ファイルに同じマークアップが重複していました）。
  ナビの項目と並びは `src/config/nav.js` が唯一の正で、各ページは
  `navActive` / `mobileNavActive` に key を渡して現在地を示します。
- **押したときの手ごたえ** — 端末まかせの青い網掛けは切り、押した所へ赤い雫が落ちて
  波紋が広がるように出しています（濃い地の上では白）。`main.js` の `initRipple`。
  出るのは遷移先のある `<a href>` とボタンだけで、見出しや飾りには出ません。
  タッチでは、指を置いてから 10px 以上動いたらスワイプとみなして出しません
  （`pointerdown` で即出すと、一覧をなぞっただけで波紋が出てしまうため）。
  短いタップは離した時点、押しっぱなしは 90ms で出します。マウスは即時です。
- **大会カルーセル** — カード下の点で現在位置が分かります（押すとその大会まで送ります）。
  `TODAY` の線はビルドした日の日本時間です（`src/data/tournaments.js`）。
  VIEW ALL を押すと全件が別画面で開き、横並びのカードが縦に並び直します。
- **大会一覧・カレンダー** — 大会情報ページは、先に一覧（`ScheduleTable`）、そのあとに
  カレンダー（`ScheduleCalendar`）の順です。どちらも `src/data/schedule.js` から作ります。
  一覧の列は 期日／大会名・種目／会場／予備日／予備会場／締切／登録区分。
  登録区分は 県＝白地に赤・市＝赤地に白・不要＝グレー地に白（`.reg--ken/shi/free`）。
  カレンダーは1か月ずつ出し、前後のボタンで月を移します（マス目は全月ぶん書き出してあり、
  JSは表示の切り替えだけなので、JSが無くても先頭の月は読めます）。
  予備会場は原稿に無いため空で、表では「—」と出ます。分かりしだい `spareVenue` に入れてください。
- **リンクのバナー** — トップのマーキーは白いカードの枠を出さず、バナーそのものを見せます。
  押している間だけ太い赤枠が出ます。手を離してから3秒でまた流れ出します。
  バナーを別タブで開くと `mouseleave` が来ないまま離れることがあるので、
  画面を離れた・戻ってきた時点でも止まった状態を必ず解除しています
  （これが無いと、戻ってきたときに流れが止まったままになります）。
- **フッターの背景** — 地の黒とわずかに色の違う四角を、大きさも位置もばらばらに散らして
  ゆっくり漂わせています（`SiteFooter.astro` の `.footer-deco`）。
  位置・大きさ・色・速さは要素ごとの変数で持たせた決め打ちで、毎回同じ見た目になります。
- **お知らせ** — `src/data/news.js` が唯一の正。トップは上から4件を出し、5件目があるときは
  続きがあることが分かるよう薄く重ねます。VIEW ALL（または5件目）で全件が別画面で開き、
  右上の × か Esc で閉じます。日付がビルド時点から2週間以内のものには赤い `NEW` が自動で付くので、
  手で付け外しはしません（記事を足して push すれば付き直ります）。
- **コート案内の地図** — `src/data/courts.js` が唯一の正。地図は緯度経度を持たず、施設名で
  Googleマップに引いてもらう埋め込み（APIキー不要）です。上のボタンで施設を切り替えます。
  施設名を直せば地図の出方も変わります。
  以前は「鳥取市 テニスコート」の地域検索で1枚にまとめていましたが、Googleの検索結果が
  そのままピンになり、協会が使わないコートまで並んでしまうため取りやめました。
  3施設だけをピンで1枚に出したい場合は、各施設の緯度経度をもらって地図を自前で描く作りに
  差し替えてください（`COURTS` に `lat`/`lng` を足す想定）。
- **アイコン** — `src/components/Icon.astro` に置いた面のアイコンを `currentColor` で出します
  （`list` は種目、`pin` は会場・コート）。
- **通知バーの表示** — トップページと大会情報ページのみ。`Base` に `notice` を渡した場合に出ます。
- **大会カルーセル** — トップの大会カードは `src/data/tournaments.js` の配列から生成されます。
  大会の追加・並び替え・状態（受付中／受付終了など）の変更はこのファイルだけで完結します。
  写真は `public/assets/img/tournaments/` に置き、各大会の `image` にパスを書けば差し込まれます。
  `image` が `null` の大会は、写真が届くまで大会名だけのプレースホルダーを表示します。

## 公開前に差し替えが必要なもの

1. **写真** — `public/assets/img/` の hero / cta / t1〜t4 は参考画像から切り出した低解像度の仮素材です。
   実写真（できれば2倍解像度）に差し替えてください。
   大会写真は `public/assets/img/tournaments/` に置き、`src/data/tournaments.js` の
   `image` / `imageAlt` を書き換えれば差し込めます（HTMLを触る必要はありません）。
2. **PDF・外部リンク** — 大会日程、登録用紙、結果PDF、リンク集の各URLは `href="#"` のままです。
3. **Googleカレンダー** — 斜線のプレースホルダー部分に iframe を挿入してください。
   モバイル（〜639px）では非表示にしています。コート案内の地図は実装済みです。
4. **お問い合わせフォーム** — 現状は入力検証と完了画面のみのフロントエンド動作です。
   送信先（メール送信／フォームサービス）の接続が必要です。
5. **`要確認` バッジの箇所** — 会長氏名、所在地、住所表記（布勢／ヤマタ）、登録費の内訳、
   ロゴ使用許諾など、赤いバッジを付けた箇所は協会への確認後に確定してください。

## 既知の検討事項

- ヘッダーは白背景で固定したため、ヒーロー写真はヘッダーの下から始まります。
  写真の上端が詰まって見える場合は `.hero__photo` の `object-position` で寄せを調整してください。
