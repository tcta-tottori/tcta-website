# 鳥取市テニス協会 公式サイト

鳥取市テニス協会（TOTTORI-CITY TENNIS ASSOCIATION）の公式サイトです。
[Astro](https://astro.build/) に CMS の [EmDash](https://github.com/emdash-cms/emdash) を組み込み、
Cloudflare Workers で公開しています（2026-10-21 に GitHub Pages から移行。[`docs/emdash.md`](./docs/emdash.md)）。
公開 URL は https://tcta-site.tcta-admin-worker.workers.dev/ 。
お知らせ・大会・イベント情報は管理画面（`/_emdash/admin/`）と AI（MCP）から更新でき、
ページはリクエストごとに描いて Workers Cache が静的 HTML と同じ速さで返します。

## ローカルでの確認

```bash
npm install                                  # 初回のみ
npx emdash secrets generate --write .env     # 初回のみ（手元用の暗号鍵）
npm run dev                                  # http://localhost:4321 を開く
```

管理画面は http://localhost:4321/_emdash/admin/ 。手元では D1 と R2 の代わりに `.wrangler/` に保存されます。
内容（お知らせ・大会）を入れる手順は [`docs/emdash.md`](./docs/emdash.md) の「運用のメモ」を参照してください。
保存すると自動で再読み込みされます。公開されるものと同じビルドを確認する場合は `npm run build`。

## 公開（Cloudflare Workers）

`main` への push で [`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml) が動き、
ビルドして Cloudflare Workers に配備します（リポジトリの Secrets に `CLOUDFLARE_API_TOKEN` と
`CLOUDFLARE_ACCOUNT_ID` が必要）。手元からは `npm run deploy`。

はじめての配備（D1・R2 の作成、暗号鍵、初回セットアップ、編集者の招待）は
[`docs/emdash.md`](./docs/emdash.md) の「設置手順」のとおりに行ってください。
内容は D1 にあるので、配備しても消えません。

ページ内のリンクはすべて相対パスなので、`*.workers.dev` でも独自ドメインでも設定を変えずに動きます。
独自ドメインは `wrangler.jsonc` の `routes` で付けます。

## 実装メモ

- **デザイン基準** — 配色・タイポグラフィ・余白・バッジの規則はデザイン仕様書 v3.1 に準拠。
  CSS変数は `public/assets/css/style.css` 冒頭の `:root` に集約しています。
- **レスポンシブ** — モバイルファースト。ブレークポイントは `〜639px` / `640〜1023px` / `1024px〜`。
  375px幅で横スクロールが出ないことを確認済みです
  （大会カルーセルの横スワイプと、大会一覧表の横スクロールは仕様どおりの例外）。
- **ヘッダー** — 全ページ共通で白背景。下端に薄い黒の1px境界線を引き、ヒーロー写真は
  透けさせません。画面上部に追従し、**下へ読み進めると引っ込み、上へ戻すと出てきます**
  （ページ上部と、モバイルメニューを開いているあいだは常に表示）。
  セクションの見出しは貼り付けません。
  画面右上の赤い「お問い合わせ」ブロックは画面右端に幅160pxで固定され、
  ナビはその手前で止まるよう `padding-right` を計算しています。
  1023px以下は全ページ共通のハンバーガーメニュー。開くと項目（下線つきの行）がヘッダーの下から上から順に滑り出し、速く出てゆっくり位置につきます（全体で0.5秒ほど）。
  閉じるときは下の項目から順にヘッダーの下へ戻ります（`.mobile-nav__item` の `--i` / `--n` から遅れを計算）。
  メニューのリンクを押したときは、次のページが描ける状態になるまでメニューを開いたまま待ち、
  描けるようになったら次のページの上でこの閉じる動きを流します（ページ間ビュートランジション。
  `style.css` の `@view-transition` と `::view-transition-old(mn-item-*)`、`Base.astro` の pageswap / pagereveal、
  `main.js` の initHeader）。対応していないブラウザでは、閉じる動きのあとに移動します。
- **ヒーローの高さ** — `calc(100svh - var(--header-h) - 1px)` でちょうど1画面ぶん。
  ヘッダーが追従しないので、この高さで次のセクションが覗かなくなります。
- **ヒーローの見出し位置** — デスクトップは左の列の上寄せに「PLAY BEYOND.」〜ボタンまでをまとめ、
  右に写真を置きます。モバイルは写真の上に重ねます（同じ格子のマスに置いて切り替えています）。
- **CSS・JS のキャッシュ対策** — `astro.config.mjs` がビルド時に中身のハッシュを計算し、`Base.astro` が
  URL に付けます（`style.css?v=xxxxxxxx`）。ファイル名を変えずに更新しているため、これが無いと
  ブラウザが古い CSS を使い続け、新しい HTML と噛み合わずに表示が崩れます。
- **URL と描画** — `src/pages/about.html.astro` のようにファイル名に `.html` を含め、移行前と同じ URL を保っています。
  ページはリクエストごとに描き（`output: 'server'`）、EmDash の内容は `src/lib/cms.js` が1リクエストに1回だけ読みます。
  公開ページは Workers Cache に1日置かれ、管理画面で公開するとそのタグのキャッシュが消えます（`astro.config.mjs` の `routeRules`）。
- **画面いっぱいの帯** — 大会カルーセルとリンク集のマーキーはコンテナの外に出し、
  画面の端から端まで使います。カルーセルは1枚目だけ本文と同じ位置から始まるよう
  内側に余白（`--carousel-pad`）を取っています。
- **ヒーローの導入** — 写真を払ったあと、右上に大きく `PLAY`、続けて左下に `BEYOND.` を
  1語1秒で出して消し、そこから「PLAY BEYOND.」のキャッチコピーが動き出します。
  キャッチコピーは文字を1枚だけ置き、背景のグラデーションを文字型に切り抜いて流すことで
  面の色だけを変えています（2枚重ねると字がずれて立体的に見えるため重ねません）。
  続けて英字（TOTTORI-CITY…）が左から1文字ずつ、小さく出て少し大きくなってから
  通常の大きさに落ち着きます（全体でちょうど1秒）。
  その0.3秒後に本文が行ごとに下から起き上がります（赤い面が駆け抜ける動きは廃止しました）。
  本文の行は `LEAD_LINES` であらかじめ分けています
  （画面幅まかせの折り返しでは行ごとに動かせないため）。
  時刻の基準は `.hero` の `--intro-end`（既定 2s）で、0s にすれば導入なしで全体が前へ詰まります。
- **見出しの塗り替え（ヒーロー以外）** — `.sec-head__title` / `.page-title` / `.sub-head` は、
  出たときは薄いグレー（`--gray-300`）で、その0.1秒後から細い白のスラッシュ（`/`）が
  左から右へ走り、通ったところが黒へ変わります（`title-slash`）。
  スラッシュは `--slash` の1枚で、色の帯と同じ大きさ・位置に重ねてあります。
  セクション見出しは `.rv` が `.on` になったときに走るので、最初に出るときの1回だけです。
- **アニメーション** — 見出しの行リビール、写真のマスク表示（clip-path）、
  スクロール連動フェード＋stagger、リンクバナーのマーキー。
  マーキーは2段組みで、上段（テニス協会・連盟のHP）は右から左、下段（施設・クラブ・
  協賛など）は左から右へ流れます。段の振り分けは `src/data/links.js` の `row` です。
  `prefers-reduced-motion` に対応しています。
- **入会誘導（CTA）** — 全ページ末尾の共通ブロック（`Cta.astro`）。見出しは
  ほかの見出しと同じ塗り替え（薄いグレー → 白いスラッシュ → 黒）で出します。
  クラスは `.ink-sweep` で、画面に入って `.rv` が `.on` になってから走ります。
  JSが無いとき・動きを減らす設定・切り抜き非対応の環境では、黒い文字をそのまま出します。
- **共通パーツ** — ヘッダー／モバイルナビ／CTA／フッター／通知バーは
  `src/components/` の各コンポーネントに一本化されています。
  1箇所を直せば全ページに反映されます（移行前は10ファイルに同じマークアップが重複していました）。
  ナビの項目と並びは `src/config/nav.js` が唯一の正で、各ページは
  `navActive` / `mobileNavActive` に key を渡して現在地を示します。
- **押したときの手ごたえ** — 端末まかせの青い網掛けは切り、押した所へ赤い雫が落ちて
  波紋が広がるように出しています（濃い地の上では白）。`main.js` の `initRipple`。
  出るのは遷移先のある `<a href>` とボタンだけで、見出しや飾りには出ません。
  タッチでは、指を置いてから 10px 以上動いたらスワイプとみなして出しません
  （`pointerdown` で即出すと、一覧をなぞっただけで波紋が出てしまうため）。
  短いタップは離した時点、押しっぱなしは 90ms で出します。マウスは即時です。
- **大会カルーセル** — カード下の点で現在位置が分かります（押すとその大会まで送ります）。
  `TODAY` の日付は見ている人の端末で毎回書き直すので、常に今日（日本時間）になります
  （`main.js` の `initToday`）。JSが無いときはページを描いた時点の日本時間を出します
  （`src/data/tournaments.js`）。
  VIEW ALL を押すと全件が別画面で開き、横並びのカードが縦に並び直します。
- **大会一覧・カレンダー** — 大会情報ページは、先に一覧（`TournamentList`）、そのあとに
  カレンダー（`ScheduleCalendar`）の順です。どちらも管理画面の「大会」（区分「協会主催」・いまの年度）から
  `src/data/schedule.js` が組み立てます。
  一覧の列は 期日／大会名・種目／会場／予備日／予備会場／締切／登録区分。
  登録区分は 県＝白地に赤・市＝赤地に白・不要＝グレー地に白（`.reg--ken/shi/free`）。
  カレンダーは1か月ずつ出し、前後のボタンで月を移します（マス目は全月ぶん書き出してあり、
  JSは表示の切り替えだけなので、JSが無くても先頭の月は読めます）。
  予備会場は原稿に無いため空で、表では「—」と出ます。分かりしだい `spareVenue` に入れてください。
- **協会の SNS** — YouTube・Instagram・X・Facebook のアカウント名は管理画面の Settings → Social に入れます。
  入れたものだけが全ページのフッター（ロゴの下）とリンク集の「協会の公式アカウント」に出ます
  （`src/data/social.js` がハンドルを URL に直し、`Icon.astro` の面のアイコンで示します）。
  LINE 公式アカウントだけは管理画面ではなく `src/data/links.js` の `LINE_OFFICIAL`（URL 固定）から、
  フッターの Instagram の横に出します（リンク集ではバナーとして出ます）。
- **リンクのバナー** — トップのマーキーは白いカードの枠を出さず、バナーそのものを見せます。
  押している間だけ太い赤枠が出ます。手を離してから3秒でまた流れ出します。
  バナーを別タブで開くと `mouseleave` が来ないまま離れることがあるので、
  画面を離れた・戻ってきた時点でも止まった状態を必ず解除しています
  （これが無いと、戻ってきたときに流れが止まったままになります）。
- **フッターの背景** — 地の黒とわずかに色の違う四角を、大きさも位置もばらばらに散らして
  います（`SiteFooter.astro` の `.footer-deco`）。動きは2つ重ねてあります。
  1つは常時の漂いで、スクロールを止めていても止まって見えないよう7〜11秒で往復します。
  もう1つはスクロール連動で、`main.js` の `initFooterDeco` がフッターの見え具合から
  `--sy`（±130px）を書き込み、四角ごとの `--depth` を掛けた分だけずらします。
  `--depth`（0.18〜1.70）は四角の大きさから決めてあるので、大きい＝手前の四角ほど
  大きく動き、小さい＝奥の四角はほとんど動かず、奥行きが出ます。
  漂いは `transform`、スクロール分は `translate` と別の枠を使っているので、
  互いに打ち消し合いません。位置・大きさ・色・速さは要素ごとの変数で持たせた決め打ちで、
  毎回同じ見た目になります。動きを減らす設定のときは両方止まります。
- **閉じるボタン** — 全画面表示（お知らせ・大会情報）の閉じるボタンは `.close-x`。
  ハンバーガーが開いているときと同じ×にそろえてあります。
- **大会の素材と成績** — 要項・申込用紙・ドロー・結果・写真は、管理画面の「大会」の
  「要項・申込用紙・ドロー・結果・当日の写真」に画像・PDF のブロックとして足します。種目ごとの優勝・準優勝は
  同じ画面の「成績」の行です。移行前に `public/assets/` へ置いた素材は「取り込みずみの素材」として残り、
  あとから足したものがその後ろに並びます（`src/data/events.js`）。
  協会主催でない大会（鳥大オープン・京丹後）は区分「預かり」の大会として同じ画面で管理します。
- **お知らせ** — 管理画面の「お知らせ」が唯一の正（`src/data/news.js` は組み立ての道具）。
  日付が見た時点から3ヶ月以内のものだけを出し、それより古いものは管理画面に残っていても表には出ません
  （消して回る必要はありません）。トップは上から4件を出し、
  5件目があるときは続きがあることが分かるよう薄く重ねます。その下の「お知らせをすべて見る」（または5件目）で3ヶ月分が別画面で開き、
  右上の × か Esc で閉じます。日付が見た時点から2週間以内のものには赤い `NEW` が自動で付くので、
  手で付け外しはしません。「目立たせる」にチェックしたものは全ページ上部の赤い帯にも出ます（これも3ヶ月以内のもの）。
- **コート案内のページ** — `courts.html`（`src/pages/courts.html.astro`）に全施設の詳細（写真・説明・住所・コート・設備・
  予約先・電話・公式ページ）を1ページに並べます。トップの一覧の行を押すとその施設の節（`courts.html#<id>`）に飛びます。
  内容は `src/data/courts.js` の `desc` / `address` / `features` / `reserve` / `tel` / `link`。
- **コート案内の地図** — `src/data/courts.js` が唯一の正。Leaflet で自前に描き（下地は国土地理院の航空写真。右上の切り替えで OpenStreetMap の地図にもできます）、
  コートの面（`src/data/court-shapes.json`）を赤く塗ってピンとラベルを置きます（`public/assets/js/main.js` の
  `initCourtMap`）。上のボタンで施設を切り替え、「すべて」で全施設を一望します。
  「すべて」では主会場（`main: true` のヤマタスポーツパーク）のピンとラベルを赤くして最前面に出し、
  他の施設のラベルに隠れないようにしています。
  「現在地」ボタンは位置情報の許可を求め、許可されれば青い点（精度の円つき）を出して、見ている施設と
  現在地が両方入る範囲に寄ります（30km より遠いときは施設だけ）。許可されない・取れないときは地図の下に
  一言出します。位置情報が使えない環境（HTTP など）ではボタンを隠します。
  以前は Google マップの埋め込みでしたが、協会が使わないコートまで並んでしまうため自前の地図にしました。
  地図の下の施設一覧は最初の3件だけを出し、4件目はお知らせと同じく薄く重ねて続きがあることを伝えます。
  「すべての施設を見る」でお知らせと同じ全画面のパネルに全施設が開き、右上の × か Esc で閉じます（`main.js` の `initFullPanel`）。
  3施設だけをピンで1枚に出したい場合は、各施設の緯度経度をもらって地図を自前で描く作りに
  差し替えてください（`COURTS` に `lat`/`lng` を足す想定）。
- **アイコン** — `src/components/Icon.astro` に置いた面のアイコンを `currentColor` で出します
  （`list` は種目、`pin` は会場・コート）。
- **通知バーの表示** — トップページと大会情報ページのみ。`Base` に `notice` を渡した場合に出ます。
- **大会情報ページの4つのボタン** — 要項 → `outline-<slug>.html`、ドロー → `draw-<slug>.html`、結果 → `result-<slug>.html`
  （それぞれ独立したページ）、申込用紙 → PDF を直接（別タブ）。素材の無いものは押せません。
  大会ページ（`event-<slug>.html`）は従来どおり全部をまとめて出します。
- **大会の結果の組み立て** — 管理画面の「結果」の画像と「当日の写真」は別々なので、公式サイト（tottori-tenis.net）の
  結果ページと画像を照合して「種目 → 結果表 → 入賞者の写真」の対応を `src/data/event-layout.json` に持っています。
  新しい結果を公式サイトに載せたあと `python3 tools/match_event_photos.py <slug>` を流すと、その大会の対応が加わります
  （URL → slug は `tools/fetch_winners.py` の PAGES）。対応の無い大会は、画像のラベルの先頭の種目名
  （「1位トーナメント 優勝 ○○ペア」など）と「成績」の種目で対応づけます。どの大会も「種目 → 結果表 → 入賞者の写真
  （写真ごとに名前）→ 入賞者の名前の1行」の同じ構成で、成績の表は別に出しません（`src/data/event-result.js`）。
- **大会カルーセル** — トップの大会カードは、管理画面の「大会」で「トップページの大会カードに出す」にチェックした
  ものが開催日順に並びます。状態（受付中／受付終了など）は「受付状態」から決まります。
  カードの種目は短い表記で1行に書き切ります（`src/data/tournaments.js` の `shortEvent`。団体戦・○○対抗戦・
  男子1部〜8部は「団体戦」だけ、「一般：男女複／ジュニア：男女単」は「一般ダブルス/ジュニアシングルス」）。
  会場も折り返しません。カードの高さは固定で、種目・会場は上揃え、ピクトグラムは文字の下のレイヤーに右下寄せで
  置きます（文字と重なっても構いません）。
  カードには写真ではなく、種目の文言から選んだピクトグラム（`src/data/event-icons.js`、画像は
  `public/assets/img/event-icons/` の シングルス／ダブルス／ミックスダブルス／団体戦 の4種）を、種目・会場の文字の
  右側に出します。「男女ダブルス」ならダブルス、「団体戦」「○○対抗戦」「男子1部〜8部」なら団体戦だけ、
  「一般：男女複／ジュニア：男女単」ならダブルスとシングルス、のように文言から決まります。
  1つずつ、画面に入った瞬間に一度だけ動きます（カルーセルを横に送って初めて見えたカードもそのとき。
  選手はスイングしてボールを打ち返す、団体戦は6人が順に跳ねて応援する。
  `src/components/EventIcon.astro`、`style.css` の `.evicon`、`main.js` の `initEventIcons`）。
  大会一覧（大会情報ページ）でも、種目は右側にピクトグラムつきで出ます。管理画面の「カードの写真」はいまは使いません。
